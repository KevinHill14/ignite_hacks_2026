FIRST TIME HERE? READ docs/TEAMMATE-SETUP.md
--------------------------------------------
It assumes you have never used an API key or a .env file, and it tells you
whether you even need one. Most tasks on this list do NOT.

Short version if you are doing design, docs, mobile, or the pitch:

    git clone https://github.com/KevinHill14/ignite_hacks_2026.git
    cd ignite_hacks_2026
    npm run gen:secrets
    npm --prefix web install
    npm run web:dev

then open http://localhost:3000 and click "See a worked example". That renders
the entire product with sample data - no API key, no Google account, no cost.

Do NOT ask Kevin for his API key. If you genuinely need one - only the tasks
that actually run the extraction pipeline do - make your own free account at
https://console.anthropic.com. Separate keys mean separate bills and no
group-wide rotation when one leaks.


WHAT'S ALREADY DONE
-------------------
- n8n pipeline (13 nodes): upload or Google Drive folder -> extract PDF text
  -> sanitize -> Claude extraction -> validate -> write Google Calendar events
- Next.js web app: upload UI, term spine graphic, cost ledger, runway
  projection
- Security pass: see docs/SECURITY.md
- Docs: README.md, docs/DEPLOY.md, docs/SECURITY.md

VERIFIED WORKING
----------------
The full pipeline has been run end to end on a real syllabus (Western
CS1026B, Winter 2026):

    18 deadlines with grade weights, 5 costs, 12 warnings
    ~40-75 seconds per run, ~$0.05 on claude-sonnet-5

Notable: the syllabus prices one required eTextbook two ways ($75.00 CAD at
the bookstore, $52.50 USD direct). The extractor emitted ONE cost and warned
not to budget for both. It also refused to invent a date for the final exam
(the Registrar sets it in March) and dropped the entry rather than guessing,
and it caught a stale term code in the bookstore link.

Still untested: Google Calendar writes (nobody has connected OAuth yet, so
calendar events currently report as failed while everything else works).

[ ] 1. Design pass on the results view
       Owner: ____________
       The look is a "carbon-copy bursar form": warm gray paper, duplicating
       machine violet, stamp red. Two rules the design depends on:
         - VIOLET always means time (deadlines)
         - RED always means money (costs)
       Nothing else may use those two colors. Keep that and the page stays
       readable at a glance.
       Files: web/src/app/globals.css (all tokens are at the top)
       Worth looking at:
         - Empty states. What does the page say before an upload? Right now
           it's plain.
         - The loading state during a ~30s pipeline run. Currently one sweeping
           bar. It could show the actual stages (reading -> extracting ->
           pricing -> filling calendar).
         - The "worth checking by hand" warnings block is the ugliest part of
           the page.

[ ] 5. Build the test corpus          <-- do this early, it unblocks everything
       Owner: ____________
       Collect 8-10 real syllabi from different faculties (arts, engineering,
       nursing, commerce, studio courses). Save them to syllabus_examples/.
       One is already in there: CS1026 (Western, Winter 2026). We need more
       variety - CS1026 has only one cost line, and arts/studio/nursing
       courses will have far messier fee structures.
       For each one, write down by hand what a human reads as the deadlines
       and the costs. That gives us ground truth to check the extractor
       against.
       What will break it, and what we most want to catch:
         - "Week 6" instead of an actual date
         - schedule tables that are images, not text
         - fees buried in a paragraph instead of a list
         - textbooks named with no price

       your real one. A bad extraction should pollute something disposable.

[ ] 7. Rate limiting on /api/ingest   <-- highest priority before going public
       Owner: ____________
       Right now anyone with the URL can upload in a loop and burn the
       Anthropic credits. Add a per-IP limit.
       File: web/src/app/api/ingest/route.ts (self-contained, low collision
       risk)

[ ] 8. Password-gate the web app
       Owner: ____________
       Anyone who reaches the URL can currently import to whatever calendar is
       connected. A single shared password in an env var is enough for a
       hackathon. Middleware is probably the cleanest place.

[ ] 9. OCR fallback for scanned syllabi
       Owner: ____________
       Scanned PDFs have no text layer. Right now the pipeline throws a clear
       error telling the user to OCR it themselves. Better: detect the short
       extraction and run OCR automatically.
       Where: the "Sanitize + Guard" node already detects this case (it throws
       when under 200 characters). Add an OCR branch before it.

[x] 10. Handle "same item, two prices" - RESOLVED, no work needed
       We expected this to break. It did not. On the real CS1026 run the
       model emitted ONE cost ($75.00 CAD) and raised a warning:
         "The $75.00 CAD and $52.50 USD prices are alternative ways to buy
          the same required eTextbook; do not budget for both."
       Leaving this noted rather than deleted, because a future syllabus may
       still trip it. If you ever see the same item double-counted across two
       currencies, the fix is to add an "alternatives" array to the cost
       schema in the "Claude: Extract Schedule + Costs" node.

[ ] 11. Retry / partial-failure handling
       Owner: ____________
       If Google Calendar rejects some events, the pipeline reports how many
       failed but there's no way to retry just those. A "retry failed events"
       button would be a nice touch.
